# ROCKNIXDS 1.5.13
**The menu stays up during DS games, and ds-fsr fits the RG DS Plus.** Quitting a DS game no longer restarts
EmulationStation: the menu is back about a second after you quit, however many games you have. And the ds-fsr shader
on the RG DS Plus draws 3× the DS screen instead of every panel pixel, which brings it back under a frame of GPU time.
**Neither change has been tried on a handheld yet**: the first one builds on the fast switching that 1.4 measured and
shipped as opt-in, the second on the RG DS's measured FSR cost.

> **RG DS Plus owners:** your release is **v1.5.13-plus**, when it is cut from this one.

## Install or upgrade

From 1.5: **Updates & downloads > ROCKNIXDS** in the menu. From anything older, ssh into the handheld as `root`
(password `rocknix`) and run:

```sh
curl -fsSL https://raw.githubusercontent.com/JorreFog/ROCKNIXDS/main/install.sh | sh
```

## ⏱️ Back to the menu in about a second, whatever the size of your library

Up to 1.5.12 a DS game stopped EmulationStation (and sway), because libdsflip needs the panels for itself, and started
them again when you quit. That start reads every system's game list again, so the loading screen after a game grew
with every game you added. 1.4's *fast switching* avoided it (the game runs on another console, and ES waits), but it
was opt-in: it had to turn ES's *HideWindow* setting off for every system, so other emulators could show ES's loading
screen on the panel they don't use.

Now the patched EmulationStation keeps its window for exactly the launches that need it (a DS game run by DraStic with
fast switching on; `es-rgds-keepwindow.patch`) and tells the launcher so, which takes the fast path only then. So:

- fast switching is **on for everyone** after this update: the menu is back about a second after you quit (1.4
  measured 1.2 s to ES answering, 1.6–1.8 s visible), and the time no longer depends on how many games you have;
- other emulators behave as on stock ROCKNIX again;
- `/storage/.config/drastic/dsflip/fast-switch off` (over ssh) goes back to stopping and starting ES, and that choice
  is kept across updates; `fast-switch on` turns it back on. The fallback stock EmulationStation always stops and starts.

Starting a game takes the same ~3.5 s as before (2.3 s of them in ROCKNIX's own launch scripts).

## 🖼️ ds-fsr on the RG DS Plus: 2× upscaled to 3×

The RG DS Plus's panels are 1024×768, 2.56× the RG DS's pixels. The FSR shader drew every one of them: at the RG DS's
measured 4.8 ms per 640×480 screen that is ~25 ms per frame for both screens, more than the 16.7 ms refresh, so it
dropped every other frame. It now draws 3× the DS screen (768×576): a 2× game is upscaled 2× → 3× by FSR's EASU (1.5×,
the ratio FSR calls *Quality*) and the display controller scales the rest to the panel, as it scales DraStic's own
frames without a shader. That is 56% of the pixels, ~14 ms per frame, which fits. On the RG DS (640×480) 3× doesn't fit
and nothing changes.

This needed a small change in the DraStic engine: a shader can now ask for its output size (`// dsflip-output: 3x` in
its source, or `WxH`; `DSFLIP_SHADER_OUTPUT` overrides it for trying other sizes). It ships as SuperDrastic
0.4.0-beta.2-rocknixds.1: the 0.4.0-beta.2 release plus that change, built the way SuperDrastic's own CI builds it;
the source patch is in `dsflip/`, for SuperDrastic's next release.

The settings advice stays: ds-fsr is the heaviest shader and runs the GPU at its full clock; ds-crisp is the light
sharp choice, and the default (bilinear) needs no GPU at all.

## ⚙️ The best settings are the defaults

The README used to ask every new player to change six Nintendo DS settings by hand. Now *Auto* is the best choice
everywhere: *3D renderer* on *Auto* runs **Gengis Engine** (the same picture as DraStic's renderer, pixel for pixel,
with about 12% less CPU work; a player who picked *DraStic* keeps it), the texture filter is the DS's own nearest, the
power profile is balanced, and the installer switches **threaded 3D** on where it was never set, as the Plus line has
done since 1.5 (uninstall removes it again). The shader stays ROCKNIX's bilinear, which needs no GPU at all.

## Notes

- Updating from 1.5.12 turns fast switching on. An older `fast-switch on` left *HideWindow* off in ES's settings; the
  update removes that override (ES decides per launch now).
- To measure the Plus: `tools/switchtime.sh <ip>` times the switch, and SuperDrastic's `tools/shaders.sh` with
  `OUT=1024x768` times every shader at the Plus's size.
